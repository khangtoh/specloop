# specloop 0.9.0

- **`specloop sync` takes upstream spec changes during a run.** A loop that
  runs for hours used to build against the specs it read at the start, so a
  phase another agent changed and pushed meanwhile went unseen. The loop now
  runs `specloop sync --apply` at each task boundary, after a box is checked
  and committed and before the next is chosen. It:
  - merges only the spec directory, plus optional `syncPaths` in
    `.specloop.json` such as plans, three ways against the upstream commit
    last synced;
  - keeps both sides' ledger entries and the run's own run-state file;
  - never rebases, pushes, or takes upstream code mid-run.

  A conflict, an uncommitted spec file, or a merged spec that fails
  `specloop check` writes nothing and exits 2, so the loop stops and someone
  reconciles. Otherwise it makes one local commit and exits 10. It then reports
  which phases, ledger entries, BACKLOG and index changed, and flags the phase
  in progress or an already-checked task that was reworded. Without `--apply`
  it only inspects.
- **Skill relationships and coordination.** Skills can declare their
  dependencies, collaborations, handoffs and conflicts, and projects can add
  their own rules in an optional `skill-coordination.md`.
- **A guide for verifying agent work** against the spec, in
  `docs/agent-quality-verifier.md`.
- **0.8.1 skills refresh cleanly.** Existing installs of the 0.8.1 skills and
  `AGENTS.md` are recognized, so `specloop refresh --agent both --apply`
  updates them without a manual merge. Customized files stay protected.

Upgrade the npm package, then preview `specloop refresh --agent both` and apply
it with `--apply`. Restart the agent to load the updated loop instructions.

The loop step is instruction text; automated checks verify the command and the
shipped instructions, not that an agent follows them in a live run.
